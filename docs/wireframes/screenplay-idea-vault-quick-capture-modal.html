Annotations

  1. [1] Global trigger mechanism — The modal should be openable from any authenticated screen via: (a) the persistent FAB (+) button in the top nav, and (b) the keyboard shortcut N. The shortcut label appears next to the modal title as a discoverability nudge. FR-05
  2. [2] Type selector as pills, not a dropdown — There are exactly 7 types — pill buttons allow single-tap selection without opening a menu. "No type yet" is the default, shown dashed to signal it's a placeholder state. Raw/untyped ideas are valid saves (FR-11 indicator will show on them in the list). The type field is technically REQUIRED per FR-01 but the UX should not block saving a raw idea. Decision needed: should a raw idea be saveable, or is type truly required? FR-02 FR-11
  3. [3] Idea textarea autofocuses on open — The cursor should land in the textarea immediately when the modal opens, so the user can start typing without clicking. The textarea is sized to ~4 lines — ideas are short by design. Voice-to-text icon (🎙) sits bottom-right of the textarea and triggers the Web Speech API. FR-01 FR-06
  4. [4] Optional section below a visual divider — Project and tags are separated by a faint "Optional" divider to communicate that the core action is type + content only. This keeps the modal feel lightweight. Project dropdown should populate from the user's existing projects (fetched on modal open). FR-03 FR-04
  5. [5] Keyboard dismissal — Esc closes the modal without saving. The hint in the footer footer reinforces this. Clicking the backdrop (outside the modal) should also dismiss with no save.
  6. [6] Validation — inline error, not toast — Validation errors appear inline below the affected field, in red, with a human-readable message. The modal stays open. Error state uses a red border + light red background on the field. NFR-02
  7. [7] Save button state — The Save button is disabled (visually dimmed) when the idea text is empty. It becomes active as soon as content is entered. This prevents empty saves without blocking the UX with a hard error upfront.
  8. [8] Post-save: modal closes + toast — On successful save: modal dismisses, user returns to wherever they were, and a short toast confirms the save. The toast includes a "View" link to jump to the new idea's detail if needed. The new idea appears at the top of the Ideas List (most-recent sort).
